Animated Artwork

Short looping videos for album and artist artwork. Albums take both a square loop (beside the cover) and a tall one (for full-bleed surfaces). Upload them by hand from the Artwork Manager page, or let the Apple Music backfill below fill albums in on a schedule.

When off, video uploads are rejected and the serve endpoints return 404.
Uploads are stored at full quality; this is the size served to clients, transcoded from the stored file on request (once per size, then cached, bitrate chosen automatically). The number is the video's short side, as in 1080p — so at 1080 a square cover is 1080×1080, a tall cover 1080×1440, and a 16:9 artist loop 1920×1080. Clients can still ask for a different size per device. Also the size the Apple backfill below aims for when picking which of Apple's renditions to store.
Custom short-side target. Set to 0 to serve originals untouched and fetch at the largest size the source offers.

Apple Music Backfill

A scheduled task that fetches animated album covers from the Apple Music animated-artwork service and files them into the slots above. Needs animated artwork enabled. Runs daily; run it on demand from Scheduled Tasks → NoriSync.

When on, the daily task backfills albums that don't already have animated artwork.
Base URL of your own apple-music-animated-artworks instance — the scraper that resolves albums to Apple's motion covers. No host is configured by default; the backfill stays idle until you set this. See the repo for Docker setup.
Which motion-cover shape to fetch, and the album image slot it fills.
Cap on albums queried per run, so the first pass over a large library doesn't hammer the service. Zero means no cap.
